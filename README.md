### [Jev corrective RAG](https://github.com/sudeshkar/jev-corrective-rag)

A corrective RAG pipeline where the yes/no decisions (is this question answerable, is this passage relevant, is this answer grounded) are typed Jev calls instead of an LLM judge. The LLM is only asked to write the answer.

`Python` `BM25` `Groq` `Streamlit`

- About 7x fewer LLM calls than the LLM-judge baseline
- Many questions are settled before they reach the generative model
- A Streamlit inspector shows each gate's verdict for every question

<summary><b>How this page is built</b></summary>

<br>

The header and every panel are SVG files in [`assets/`](assets), rendered by [`scripts/generate-cards.mjs`](scripts/generate-cards.mjs) and committed by [a scheduled workflow](.github/workflows/profile-cards.yml) every six hours.

Shared card services such as `github-readme-stats` run on one public rate limit. When it runs out, the card returns an error, GitHub's image proxy caches it, and the panel stays empty for hours. Doing the work at build time avoids that:

| Step | What happens |
| :--- | :--- |
| Fetch | `scripts/data.mjs` queries the GitHub GraphQL API with this repository's own `GITHUB_TOKEN` |
| Fall back | The result is saved to `assets/data.json`. If a run fails, the panels are drawn from the last good copy |
| Render | `scripts/cards/*.mjs` write a light and a dark SVG for each panel. Archivo, the typeface from my portfolio, is embedded in each file, so it renders the same everywhere |
| Serve | The SVGs live in this repository, so viewing the page calls no outside service |

To run it locally:

```bash
GITHUB_TOKEN=$(gh auth token) node scripts/generate-cards.mjs
```
